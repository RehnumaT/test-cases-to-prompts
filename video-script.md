# Presenter Video Script — "From Test Cases to Prompts"

For use with an AI-avatar video tool (Synthesia, HeyGen, D-ID, Colossyan, etc.) or to record yourself on camera.

## Setup notes
- **Length:** ~80 seconds (main cut). ~30 second teaser cut included below.
- **Avatar/delivery style:** professional, business-casual, calm and direct — talking to camera, not reading off a slide.
- **Background:** minimal office or soft neutral gradient — nothing that competes with the text overlays.
- **Pacing:** ~150 words/minute. Natural pause at every line break below.
- **Captions:** burn in subtitles / enable auto-captions. Most LinkedIn video plays muted by default — if there's no caption, most viewers get nothing.
- **Aspect ratio:** 1:1 or 4:5 for LinkedIn feed (fills more of the screen than 16:9 on mobile).

---

## Main cut (~80 seconds)

**[0:00–0:12] — The cause**
*On-screen text: "Software used to be predictable."*

> For years, QA was simple in one sense: input A, plus input B, always equals C. Deterministic. Testable.
> But AI doesn't work that way anymore. Now, A plus B just... usually equals C. And that "usually" is the whole problem.

**[0:12–0:30] — The goal**
*On-screen text: "The skill gap isn't technical. It's testing."*

> Companies are racing to ship AI features, but the real bottleneck isn't building the model — it's controlling what it does.
> And that's exactly the muscle QA engineers have been building their entire careers: defining expected behavior, and testing the edges where it breaks.

**[0:30–0:55] — The purpose (how it actually works)**
*On-screen text: "Test case → system prompt. Same discipline."*

> A test case has pre-conditions, inputs, and expected results. A system prompt has context, constraints, and an output format.
> They're the same document. When you write acceptance criteria, you're already doing prompt engineering — you just didn't have the title yet.

**[0:55–1:15] — The realistic outcome**
*On-screen text: "What actually changes."*

> This isn't about becoming a machine learning engineer overnight. It's smaller than that, and more useful.
> You start writing prompts your team can actually rely on. You catch the hallucination before it ships. You get pulled into the room when the product team is deciding what the AI should and shouldn't do.
> That's the shift — from gatekeeper, to architect.

**[1:15–1:22] — Close**
*On-screen text: "Read the full breakdown — link below."*

> I wrote the full breakdown, test case by test case. Link's below — let me know if it matches how you already think.
